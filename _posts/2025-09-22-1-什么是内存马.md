内存马（`Memory Shell`，或称“内存木马”）是一种只存在于 **内存中的后门程序**，不写入磁盘文件。内存马依赖进程生命周期，通常随目标进程启动而存在，进程结束或系统重启后会消失。

本质是调用`add_url_rule`动态添加路由`/shell`,配置匿名函数从**线程本地栈**`_request_ctx_stack`中拿到传入的参数shell并执行。

#### Q：什么是线程本地栈`_request_ctx_stack`
线程本地栈（`Thread-local stack`）是一种数据结构，结合了**栈**的特性和**线程本地存储**的特性，广泛用于 Web 框架（如 `Flask`）管理每个线程独立的上下文。

每个线程都有自己的存储空间。全局变量在多线程环境中是共享的，容易冲突。 线程本地存储让每个线程有自己独立的“全局变量副本”，互不干扰。

栈对象本身通常是全局的，但栈里的数据是线程独立的。

`Flask` 用 `_request_ctx_stack` 管理请求上下文。每个请求对应一个 `RequestContext` 对象，压入栈顶。因此当前请求信息通常储存在`_request_ctx_stack.top` 的栈顶。

#### Q: `add_url_rule()`在哪
`add_url_rule()`属于`Flask`类。
```
from flask import Flask

app = Flask(__name__)
app.add_url_rule()
```
源码：
```
class Flask(...):
    def add_url_rule(self, rule, endpoint=None, view_func=None, **options):
        """
        Connects a URL rule. Used internally by route() decorator.
        """
        # 实际上调用的是 werkzeug.routing.Map 来注册路由
        self.url_map.add(Rule(rule, endpoint=endpoint, **options))
        if view_func is not None:
            self.view_functions[endpoint] = view_func

```

### 2.Flask version >= 2.3
移除了内置的 `werkzeug.serving` 调试器机制和部分`request`的`hook`，很多“旧版内存马”写法失效了。

高版本`Flask`利用`_check_setup_finished()`来防御恶意添加路由。在接受第一个请求后，将`_got_first_request`设为`True`。当攻击者企图添加路由时，对`_got_first_request`进行校验，若为`True`，则报错。
